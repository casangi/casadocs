.. _Description:

Description
   Estimate the atmospheric zenith delay and clock error

   .. warning:: **WARNING: zenithdelaycal** is currently an experimental task. 
      Use with care and report issues back to the CASA team via the `NRAO helpdesk <http://help.nrao.edu/>`__.

   Given a calibration table with multi-band delays (MBDs), the **zenithdelaycal** task separates the contribution from the atmosphere and the clock using the model:
   
   .. math::
   
        Delay = Clock(t) + Atmo(t) * Airmass(elevation)

   Where Clock(t) and Atmo(t) are polynomials describing the time evolution of the clock and atmosphere, respectively, and Airmass(elevation) is the model used to describe the air mass (selected through the ``atmospheric_delay_model`` argument).
   **zenithdelaycal** finds the coefficients of the polynomials that describe the delays.
   The order of the polynomials must be specified by the user.
   For the clock, a linear polynomial is recommended (default, ``clock_polynomial_order=1``).

   In VLBI the correlator assumes a model of the clock error and atmosphere that is not perfect.
   Residual errors in the clock and atmosphere can be estimated from MBDs spanning a range of elevations.
   For more background and details on how to setup the observations please see `AIPS memo 110 <https://library.nrao.edu/public/memos/aips/memos/AIPSM_110.pdf>`_.

   **zenithdelaycal** expects a **fringefit** caltable with MBDs as input (argument ``mbdtable``).
   From this table it derives Clock(t) and Atmo(t) for each antenna in the ``mbdtable`` (unless a subset is requested using the ``antenna`` argument).
   By default a single solution is derived for all polarizations.
   A per polarization solution for Clock(t) can be obtained using ``per_pol_clock=True``.
   The clock or atmosphere terms can be disabled by setting their polynomial orders to -1.
   The solutions generated by **zenithdelaycal** can be applied using **applycal**, and like those for **fringefit** with ``combine="spw"``, require setting ``spwmap=[0]*(# spws)`` (i.e., there's only one spw in the resulting caltable labelled as 0).

   The resulting caltable has the coefficients of the polynomials used to describe the clock and atmosphere stored in units of s, s s-1 and s s-2.
   The first three coefficients are those of Atmo(t), the next three Clock(t) for the first polarization, and the last three Clock(t) for the second polarization (which will be the same as the previous three unless ``per_pol_clock=True``).

.. _Examples:

Examples
   Example of a **zenithdelaycal** call using a linear clock error and a quadratic polynomial for the atmosphere:

   ::

        zenithdelaycal(vis="data.ms",
                       caltable="data.zen",
                       refant="PT",
                       mbdtable="data.mbd",
                       clock_polynomial_order=1,
                       atmospheric_polynomial_order=2)

   The solutions can be applied using the task **applycal**, with ``spwmap=[0]*#spws``.
   For example, if ``data.ms`` contains four spectral windows:

   ::

        applycal(vis="data.ms",
                 gaintable="data.zen",
                 swpmap=[0]*4)

   As a reminder, ``mbdtable`` can be obtained by running **fringefit** with ``combine="spw"`` like:

   ::

        fringefit(vis="data.ms",
                  caltable='data.mbd',
                  combine='spw',
                  minsnr=10,
                  parang=True)

   Example of a **zenithdelaycal** call using quadratic polynomials for the clock and atmosphere:

   ::

        zenithdelaycal(vis="data.ms",
                       caltable="data.zen",
                       refant="PT",
                       mbdtable="data.mbd",
                       clock_polynomial_order=2,
                       atmospheric_polynomial_order=2)

   Example of a **zenithdelaycal** call using a secant cubed model for the air mass:

   ::

        zenithdelaycal(vis="data.ms",
                       caltable="data.zen",
                       refant="PT",
                       mbdtable="data.mbd",
                       atmospheric_delay_model="secant cubed")

   Limited testing has shown that ``atmospheric_delay_model="secant cubed"`` produces worse results than the default ``"secant"`` air mass model.

   Example of a **zenithdelaycal** call producing output plots:

   ::

        zenithdelaycal(vis="data.ms",
                       caltable="data.zen",
                       refant="PT",
                       mbdtable="data.mbd",
                       plot_delay_solution=True)

   The output plots will be stored in the current working directory as PNGs with the names ``zenithdelaycal_delay_plot_antenna-name.png``, where ``antenna-name`` is replaced by the corresponding antenna name (e.g., "PT", "SC", etc...).
